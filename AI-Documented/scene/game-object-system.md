# GameObject System

## Purpose
Introduces an entity abstraction to represent scene content in a reusable, engine-oriented format instead of hardcoded draw calls.

## Core Class: GameObject

`GameObject` encapsulates identity/topology and owns component state:

- `id`: unique `uint32_t` identifier generated by scene graph
- `name`: human-readable label used by debug UI
- `meshType`: logical model binding (`Cube`, `Plane`, `Model`)
- `parentId` + `children`: hierarchy links
- `TransformComponent`
	- `position`, `rotation`, `scale`: local transform channels
- `RendererComponent`
	- `materialColor`: per-object material tint
	- `useTexture`: controls albedo source selection in shader (`materialParams.x`)
	- `visible`: controls scene-pass participation
	- `castsShadow`: controls shadow-pass participation

## Data Flow to Rendering

Per frame, each visible `GameObject` is converted to a `RenderItem` containing:

- resolved world transform (`world`)
- resolved inverse-transpose (`worldInverseTranspose`)
- pointer to source `GameObject` (for renderer component/material access)

At draw time, `ObjectBufferData` is filled from `RenderItem` + object material flags and sent through `UpdateSubresource`.

## Transform Construction

Local transform is composed from `TransformComponent` in `ComposeTransform(const GameObject&)`:

`Scaling * RotationRollPitchYaw * Translation`

This local transform is then combined with parent world transform during scene-graph traversal.

## Runtime Behavior

- The spinning cube is now represented as a `GameObject` (`SpinningCube`) and animated by updating its local Y rotation every frame.
- Ground plane is represented as a `GameObject` (`GroundPlane`) with `castsShadow=false` to preserve prior shadow behavior.
- Any selected object can now be edited at runtime through Inspector component controls.

## Notes

- This architecture decouples object definition from render-pass code.
- Additional meshes/material models can be integrated by extending `MeshType` and mesh lookup mapping.
